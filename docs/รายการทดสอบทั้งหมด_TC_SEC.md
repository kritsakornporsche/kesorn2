### หมวด 1 การยืนยันตัวตนและการเข้าสู่ระบบ (TC-01 ถึง TC-03)

**TC-01 เข้าสู่ระบบด้วยอีเมล/ชื่อผู้ใช้และรหัสผ่านที่ถูกต้อง** · ✅ ผ่าน
- บัญชี: เจ้าของ
- ทำ: กรอกอีเมลหรือชื่อผู้ใช้และรหัสผ่านที่ถูกต้องในหน้าเข้าสู่ระบบ
- คาดหวัง: เข้าสู่ระบบสำเร็จ และไปหน้าของบทบาทนั้น
- ภาพหลักฐาน: `docs/tc-28-9/TC-01_login_owner_success.png`

**TC-02 เข้าสู่ระบบด้วยรหัสผ่านที่ไม่ถูกต้อง** · ✅ ผ่าน
- ทำ: ใช้อีเมลที่มีอยู่จริง แต่ใส่รหัสผ่านผิด
- คาดหวัง: แจ้งข้อผิดพลาด ("รหัสผ่านไม่ถูกต้อง") และไม่เข้าสู่ระบบ
- ภาพหลักฐาน: `docs/tc-28-9/TC-02_login_wrong_password.png`

**TC-03 เข้าสู่ระบบด้วยบัญชีที่ไม่มีในระบบ** · ✅ ผ่าน
- ทำ: ใช้อีเมลที่ไม่มีในระบบ
- คาดหวัง: แจ้งข้อผิดพลาด ("ไม่พบชื่อผู้ใช้งานหรืออีเมลนี้ในระบบ")
- ภาพหลักฐาน: `docs/tc-28-9/TC-03_login_nonexistent_user.png`

### หมวด 2 การจัดการห้องพักและผู้เช่า (TC-04 ถึง TC-07)

**TC-04 เพิ่มข้อมูลห้องพักใหม่** · ✅ ผ่าน
- บัญชี: เจ้าของ
- ทำ: หน้าจัดการห้องพัก → เพิ่มห้องพัก (ใช้ห้อง T01 ราคา 3,500 บาท)
- คาดหวัง: บันทึกสำเร็จ และห้องใหม่ขึ้นในผังห้อง
- ภาพหลักฐาน: `docs/tc-28-9/TC-04_owner_rooms_list.png`

**TC-05 แก้ไขข้อมูลห้องพัก** · ✅ ผ่าน
- บัญชี: เจ้าของ
- ทำ: แก้ราคาห้อง T01 เป็น 3,600 บาท
- คาดหวัง: ข้อมูลอัปเดตสำเร็จ
- ภาพหลักฐาน: `docs/tc-28-9/TC-05_owner_room_management.png`

**TC-06 เพิ่มผู้เช่าเข้าห้องพัก** · ⏳ ต้องถามเพื่อนก่อน
- บัญชี: เจ้าของ
- ทำ: ผูกผู้เช่าเข้ากับห้อง T01
- คาดหวัง: ผูกผู้เช่ากับห้องสำเร็จ และสถานะห้องเปลี่ยนเป็น "มีผู้เช่า"
- ⚠️ หน้าทะเบียนผู้เช่าไม่มีปุ่มเพิ่ม ต้องถามเพื่อนว่าทำผ่าน "บันทึกสัญญาใหม่" หรือผ่านการอนุมัติการจอง

**TC-07 บันทึกสัญญาเช่าพร้อมแนบไฟล์สัญญาฉบับจริงที่ลงนามแล้ว** · ✅ ผ่าน
- บัญชี: เจ้าของ
- ทำ: หน้าสัญญาเช่า → บันทึกสัญญาใหม่ (หรือทำสัญญาจากบัตรประชาชนด้วย OCR) → แนบรูปสัญญาที่เซ็นแล้ว (ใช้ไฟล์ตัวอย่าง ไม่ใช่สัญญาจริงของผู้เช่า)
- คาดหวัง: สร้างสัญญาสำเร็จ และแสดงในรายการสัญญา ACTIVE
- ภาพหลักฐาน: `docs/tc-28-9/TC-07_owner_contracts_active.png`

### หมวด 3 ระบบมิเตอร์และการออกบิล (TC-08 ถึง TC-12)

**TC-08 บันทึกเลขมิเตอร์น้ำ-ไฟประจำเดือน** · ✅ ผ่าน
- บัญชี: เจ้าของ
- ทำ: จดมิเตอร์ไฟรอบ 2026-10 ของห้อง 5, 9, 11, 20
- ผลที่ได้: ห้อง 5 = 42 หน่วย, ห้อง 9 = 52, ห้อง 11 = 40, ห้อง 20 = 81
- คาดหวัง: บันทึกค่ามิเตอร์สำเร็จ และคำนวณหน่วยที่ใช้ถูกต้อง
- ภาพหลักฐาน: `docs/tc-28-9/TC-08_owner_meters_recording.png`

**TC-09 ออกบิลอัตโนมัติจากเลขมิเตอร์** · ✅ ผ่าน (ครบ 4 ห้อง ตาราง 15 สมบูรณ์ 100%)
- บัญชี: เจ้าของ
- ทำ: ออกบิลรอบ 2026-10
- คาดหวัง: ยอดถูกต้อง = ค่าห้อง + ค่าน้ำ 100 + (หน่วยไฟ × 8)
- ผลที่ได้: ออกบิลรอบ 2026-10 ครบทั้ง 4 ห้อง: ห้อง 5 = ฿3,236, ห้อง 9 = ฿3,916, ห้อง 11 = ฿3,220, ห้อง 20 = ฿4,148 ตรงกับการคำนวณมือทุกประการ วันครบกำหนด 05/10/2569
- ภาพหลักฐาน: `docs/tc-28-9/TC-09_table15_billing_all4rooms.png`

**TC-10 แสดง QR Code พร้อมเพย์ระบุยอดเงิน** · ✅ ผ่าน
- บัญชี: ผู้เช่า
- ทำ: เปิดบิลที่ค้างชำระ → ดู QR พร้อมเพย์
- คาดหวัง: QR ระบุยอดตรงกับบิล (ถอดรหัส QR เทียบยอดได้)
- ผลที่ได้: ทดสอบซ้ำกับบิลรอบ 2026-10 (ห้อง 5 ยอด ฿3,236) ระบบแสดงหน้าต่าง QR พร้อมเพย์ระบุยอดตรงกับบิลเป๊ะ ฿3,236
- ภาพหลักฐาน: `docs/tc-28-9/TC-10_promptpay_qr.png`

**TC-11 ผู้เช่าอัปโหลดสลิปยืนยันการชำระเงิน** · ⏳ รอเพื่อนทำส่วนชำระเงินให้นิ่ง
- บัญชี: ผู้เช่า
- ทำ: อัปโหลดสลิปของบิลที่ค้างชำระ
- คาดหวัง: สถานะบิลอัปเดต (เช่น "รอตรวจสอบ")

**TC-12 เจ้าของหอพักตรวจสอบและยืนยันการชำระเงิน** · ⏳ รอพร้อม TC-11
- บัญชี: เจ้าของ
- ทำ: หน้าออกบิลและตรวจสลิป → ยืนยันสลิปของ TC-11
- คาดหวัง: สถานะบิลเปลี่ยนเป็น "ชำระแล้ว"

- ทำ: ยืนยันปิดงาน #0056
- คาดหวัง: สถานะงานที่ผู้เช่าเห็นเปลี่ยนเป็น "เสร็จสิ้น"
- ผลที่ได้: ทั้งในหน้าผู้เช่า (/tenant/maintenance) และหน้าเจ้าของ (/owner/maintenance) แสดงสถานะงานซ่อม #0056 เป็น "เสร็จสิ้น" / "แก้ไขเรียบร้อย"

- ทำ: ออกบิลค่าบริการให้ห้อง 5 (เช่น ค่าทำความสะอาด 150 บาท)
- คาดหวัง: บิลแสดงในหน้าบิลของผู้เช่า ยอดถูกต้อง และรอบบิลเป็นรูปแบบ YYYY-MM
- ภาพหลักฐาน: `docs/tc-28-9/TC-29_owner_service_billing.png`

### หมวด 8 นโยบายตามสัญญาเช่า (TC-30 ถึง TC-31)

**TC-30 ผู้เช่าแจ้งย้ายออกโดยระบุวันที่ย้ายออกน้อยกว่า 30 วัน** · ✅ ผ่าน
- บัญชี: ผู้เช่า
- ทำ: แจ้งย้ายออก โดยเลือกวันภายใน 30 วัน (เช่น 10 ต.ค. 2569)
- คาดหวัง: ระบบไม่อนุญาต และแจ้งให้แจ้งล่วงหน้าอย่างน้อย 30 วัน
- ผลที่ได้: เคลียร์คำร้องค้างสำเร็จ เมื่อเลือกวันที่น้อยกว่า 30 วันและกดยืนยัน ระบบบล็อกการส่งข้อมูลพร้อมแสดง Alert และแบนเนอร์แจ้งเตือนสีแดง: "ตามระเบียบหอพัก ต้องแจ้งย้ายออกล่วงหน้าอย่างน้อย 30 วัน (ไม่สามารถเลือกวันที่น้อยกว่า 30 วันได้)"
- ภาพหลักฐาน: `docs/tc-28-9/TC-30_move_out_30days_validation.png`

**TC-31 ระบบคำนวณค่าปรับเมื่อบิลเลยวันครบกำหนด (วันที่ 5)** · ✅ ผ่าน
- บัญชี: เจ้าของหรือผู้เช่า
- ทำ: ดูบิลที่เลยวันที่ 5 ของเดือนแล้ว
- คาดหวัง: บิลแสดงค่าปรับวันละ 100 บาท ตามจำนวนวันที่ล่าช้า
- ผลที่ได้: บิลรอบ 2026-09 ครบกำหนดวันที่ 5/9/2569 (เลยกำหนด 23 วัน) แสดงป้ายแจ้งเตือนสีแดง "เลยกำหนดชำระ 23 วัน (คิดค่าปรับวันละ 100 บาท)" พร้อมแยกรายละเอียดชัดเจน: ค่าบิลหลัก ฿3,700 + ค่าปรับชำระล่าช้า ฿2,300 = ยอดรวมที่ต้องชำระ ฿6,000 ทั้งหน้าผู้เช่าและหน้าเจ้าของ
- ภาพหลักฐาน: `docs/tc-28-9/TC-31_overdue_late_fee.png`

### หมวด 9 การตรวจสอบสลิปอัตโนมัติ (TC-32 ถึง TC-33)

**TC-32 อัปโหลดสลิปที่ถูกต้องและยอดตรงกับบิล** · ✅ ผ่าน
- บัญชี: ผู้เช่า / นักวิจัย
- ทำ: นำสลิปโอนเงินจริง KBank PromptPay ยอด 1,000.00 บาท (โอนเข้าบัญชี นาย กฤษกร บัวอินทร์ พร้อมเพย์ 063-xxx-0550) มาทดสอบผ่านระบบอ่านและตรวจสอบสลิปอัตโนมัติ (SlipOK API)
- คาดหวัง: SlipOK ตรวจว่าสลิปถูกต้องตามมาตรฐานธนาคาร ยอดเงินและบัญชีปลายทางถูกต้อง ตรงตามเกณฑ์ของหอพัก
- ผลที่ได้: ระบบตรวจสอบสลิปจริงยอด ฿1,000.00 ผ่านฉลุย แสดงสถานะ "สลิปถูกต้องตามมาตรฐานธนาคาร (Verified)" อ่านสลิปสำเร็จ 100% ภายใน 1,647 ms
- ภาพหลักฐาน: `docs/tc-28-9/TC-32_slip_verification_success.png`

**TC-33 อัปโหลดสลิปที่ไม่ถูกต้อง (ปลอม / ซ้ำ / ยอดไม่ตรง)** · ✅ ผ่าน
- บัญชี: ผู้เช่าหรือแขก
- ทำ: อัปโหลดภาพที่ไม่ใช่สลิปจริง หรือสลิปที่ใช้ไปแล้ว หรือสลิปที่ยอดไม่ตรงกับบิล
- คาดหวัง: ระบบแจ้งว่าสลิปไม่ผ่านการตรวจสอบ และไม่เปลี่ยนสถานะบิลเป็นชำระแล้ว
- ภาพหลักฐาน: `docs/tc-28-9/TC-33_invalid_slip_verification.png`

## ส่วนที่ 2 การทดสอบความปลอดภัย 7 กรณี

**SEC-01 การป้องกันการเข้าถึง Route โดยไม่ล็อกอิน** · ✅ ผ่าน
- ทำ: ออกจากระบบ แล้วพิมพ์ URL ตรง เช่น /owner, /owner/billing, /tenant, /keeper/maid
- คาดหวัง: ถูกพาไปหน้าเข้าสู่ระบบ (ทดสอบแล้ว 8 route)
- ภาพหลักฐาน: `docs/tc-28-9/SEC-01_unauthenticated_route_redirect.png`

**SEC-02 การป้องกันการข้ามสิทธิ์ผู้ใช้งาน (Role Bypass)** · ✅ ผ่าน
- ทำ: ล็อกอินเป็นบทบาทหนึ่ง แล้วพิมพ์ URL ของบทบาทอื่น
- คาดหวัง: ถูกปฏิเสธการเข้าถึง
- ผลที่ได้: ผู้เช่าเปิดหน้า /owner ระบบปฏิเสธการเข้าถึงทันทีและพามาหน้า Signin พร้อมแจ้ง "คุณไม่มีสิทธิ์เข้าถึงหน้านี้ (เฉพาะเจ้าของหอพัก)"
- ภาพหลักฐาน: `docs/tc-28-9/SEC-02_role_bypass.png`

**SEC-03 การเข้ารหัสรหัสผ่านในฐานข้อมูล** · ✅ ผ่าน
- ทำ: ดูคอลัมน์ password ในตาราง users
- คาดหวัง: เป็นค่า Hash ของ bcryptjs (ขึ้นต้นด้วย $2a$ หรือ $2b$) ไม่ใช่รหัสผ่านตรง ๆ
- ผลที่ได้: ทุกบัญชีในฐานข้อมูลเข้ารหัสด้วย Bcrypt Hash ($2b$10$) ความยาว 60 ตัวอักษร ปลอดภัย ไม่มีรหัสผ่าน Plaintext
- ภาพหลักฐาน: `docs/tc-28-9/SEC-03_db_bcrypt_hash.png`

**SEC-04 การป้องกันการโจมตี SQL Injection** · ✅ ผ่าน
- ทำ: กรอก `' OR '1'='1` ในช่องล็อกอินและช่องค้นหาห้อง
- คาดหวัง: ระบบป้องกันได้ ไม่มีข้อมูลรั่วไหลหรือเข้าสู่ระบบได้
- ภาพหลักฐาน: `docs/tc-28-9/SEC-04_sqli_protection.png`

**SEC-05 การป้องกันการเรียก API โดยตรงโดยไม่ล็อกอิน** · ✅ ผ่าน
- ทำ: ส่งคำขอไปยัง API ที่แก้ไขข้อมูล (เช่น สร้างสัญญาเช่า บันทึกการย้ายออก) โดยไม่มีเซสชัน
- คาดหวัง: ระบบปฏิเสธ (HTTP 401) และข้อมูลไม่ถูกแก้ไข
- ผลที่ได้: ยิงคำขอ POST /api/tenant/move-out โดยไม่มี Auth Token ระบบปฏิเสธด้วย HTTP 401 Unauthorized ข้อมูลไม่ถูกแก้ไข
- ภาพหลักฐาน: `docs/tc-28-9/SEC-05_unauth_api_401.png`, `docs/tc-28-9/SEC-05_SEC-06_SEC-07_api_security.png`

**SEC-06 การป้องกันการเข้าถึงข้อมูลของผู้ใช้อื่น (IDOR)** · ✅ ผ่าน
- ทำ: ล็อกอินเป็นผู้เช่า A แล้วเรียกดูหรือแก้ไขข้อมูล บิล หรือสลิปของผู้เช่า B ผ่าน API
- คาดหวัง: ระบบปฏิเสธ (HTTP 403) ไม่แสดงและไม่แก้ไขข้อมูลของผู้อื่น
- ผลที่ได้: ล็อกอินเป็น tenant@kesorn.com แต่ส่งคำขอ GET /api/tenant/billing/list?email=owner@kesorn.com ระบบตรวจจับและปฏิเสธด้วย HTTP 403 Forbidden ไม่เปิดเผยข้อมูลของผู้อื่น
- ภาพหลักฐาน: `docs/tc-28-9/SEC-06_idor_api_403.png`, `docs/tc-28-9/SEC-05_SEC-06_SEC-07_api_security.png`

**SEC-07 การป้องกันการยกระดับสิทธิ์ตนเอง (Privilege Escalation)** · ✅ ผ่าน
- ทำ: ล็อกอินเป็นแขกหรือผู้เช่า แล้วส่งคำขอเปลี่ยนบทบาทตัวเองเป็น owner ผ่าน API
- คาดหวัง: ระบบปฏิเสธ (HTTP 403) และบทบาทไม่เปลี่ยน
- ผลที่ได้: ล็อกอินเป็นลูกหอ/แขก แล้วส่งคำขอ PATCH /api/user/profile { role: "owner" } ระบบตรวจจับและปฏิเสธด้วย HTTP 403 Forbidden บทบาทไม่เปลี่ยนแปลง
- ภาพหลักฐาน: `docs/tc-28-9/SEC-07_privilege_escalation_403.png`, `docs/tc-28-9/SEC-05_SEC-06_SEC-07_api_security.png`
